## Current failure

Running the current `samu` in a disposable REM guest reaches graph parsing and
log initialization, then fails before `samu -n` completes. With a manifest
containing `builddir = /root`, the diagnostic includes a malformed path such
as:

```text
samu: `\x01/.ninja_log.tmp:
Hangup
```

Changing the build directory to `/tmp` still produces a malformed prefix. A
variant without a build directory reaches a later segmentation fault.

This means the old stat/mtime theory is closed. The remaining boundary is the
formatted variadic path used by:

```text
loginit
  -> xasprintf("%s/%s", builddir, logname)
  -> vsnprintf
```

## ABI evidence

GCC REM output and chibicc output agree on the current variadic ABI:

- callers do not reserve a home area for register-only calls;
- variadic callees save incoming `r1`–`r4` at old-SP offsets `16..28`;
- with two named pointer parameters, `va_start` points at old-SP+24, the
  incoming `r3` slot;
- the ordinary function ABI remains `r1`–`r4` arguments, `r1` return, `r13`
  stack pointer, `r14` link register, and 16-byte call-boundary alignment.

The generated `xasprintf` assembly uses the expected old-SP+24 cursor, and
the generated caller passes `&logpath`, format, `builddir`, and `logname` in
`r1`–`r4`. Therefore do not reapply the previously disproven change that
reserved a 32-byte home area for every variadic call.

## Important reducer results

- A direct flexible-string allocation/copy reducer prints `/root` correctly.
- `struct stat` is 128 bytes in both the REM chibicc and GCC target models.
- GCC and chibicc `getbuilddir`, `loginit`, `osmkdirs`, and variadic save-area
  assembly are structurally consistent.
- `printf("%d", 42)` and the earlier chibicc-to-GCC/musl `vfprintf` regression
  pass, but a two-pointer formatted call has not yet been executed in a clean
  guest.
